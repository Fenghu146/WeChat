## 3. 自动演示（`--demo`）

### 3.1 全量演示

```bash
./build/demo_fh --demo                  # Windows：.\build\Debug\demo_fh.exe --demo
```

A→D 四段依次跑完，然后进入手动工作台。在**交互终端**下，每段之间会停下等回车：

```
  —— 回车继续下一段演示 ——
```

（管道/重定向环境下自动跳过暂停，所以脚本里用不受影响。）

### 3.2 只演示某一段

```bash
./build/demo_fh --demo=A    # A 核心流程：QQ 群 vs 微信群
./build/demo_fh --demo=B    # B 多产品账号 / 开通 / 登录联动（任务书 1·4·5）
./build/demo_fh --demo=C    # C 好友 / 群注册表 / QQ 临时讨论组
./build/demo_fh --demo=D    # D 群消息平台差异
```

（Windows：把 `./build/demo_fh` 换成 `.\build\Debug\demo_fh.exe`。）

答辩时建议：先 `--demo=A` 讲策略模式，再按问题切 `--demo=B/C/D`，不必每次从头放。

### 3.3 看结尾的「演示自检汇总」

每段演示结束都会输出汇总，格式如下（**全量实测结果**）：

```
======== 演示自检汇总 ========
  校验项 66 项：成功 46，失败 20（其中标注「应失败」的平台规则 / 权限校验 20 项）
  自检结果：全部符合预期
```

各段单独运行的预期数字（可与自己的运行结果对照）：

| 命令 | 校验项 | 成功 | 失败（均为「应失败」） |
|---|---:|---:|---:|
| `--demo=A` | 28 | 19 | 9 |
| `--demo=B` | 11 | 7 | 4 |
| `--demo=C` | 14 | 11 | 3 |
| `--demo=D` | 13 | 9 | 4 |
| `--demo`（全量） | **66** | **46** | **20** |

四段之和 = 全量（28+11+14+13 = 66，9+4+3+4 = 20），可用于自检统计是否漏项。

**若出现「应成功却失败」或「应失败却成功」，汇总会显示为红色并列出条数** ——
这就是演示代码出问题时的报警，不需要人眼逐行核对。

### 3.4 颜色

终端下自动开启着色：

- **绿色 = 符合预期**（含被平台规则刻意拒绝的「应失败」项）
- **红色加粗 = 与预期不符**

之所以不按"成功绿/失败红"着色，是因为演示里有 20 项失败是**故意**被拒绝的，
按成败着色会让真正的异常淹没在一片红色里。

```bash
FH_DEMO_COLOR=1 ./build/demo_fh --demo    # 强制着色（例如输出被重定向时）
NO_COLOR=1 ./build/demo_fh --demo         # 关闭着色
```

## 4. 手动工作台

```bash
./build/demo_fh          # 不带参数，直接进工作台
```

（Windows：`.\build\Debug\demo_fh.exe`。必须在仓库根目录运行 —— 工作台启动时从当前
目录读 `save_*.dat` 存档。）

操作约定：**全部为数字键，按一下即触发，不需要回车**；每次操作后界面自动重绘，
底部提示条显示 `[成功]` / `[失败]` / `[提示]` 及原因。列表型界面的功能键
**按列表长度动态编号**，以屏幕实际显示为准。

选择列表（加/删好友、发微博关注、邀请成员等）会在每项后标注**当前关系**，例如
`［已是QQ好友］`/`［非QQ好友］`、`［已关注］`/`［未关注］`、`［已在群内］`/`［不在群内］`，
便于判断该点谁 —— 加好友时避开重复项，删好友时避开非好友项。

### 4.2 建议的手动走查路径（对照任务书）

#### A · 群管理（先 `[5]` 建一个 QQ 正式群）

| 操作 | 预期结果 |
|---|---|
| 群主邀请成员、任命管理员 | `[成功]` |
| 切到微信模式后，由**管理员**设置全员禁言 | `[失败]`，提示微信群仅群主为特权账号 |
| 切回 QQ 模式后，同一管理员再设全员禁言 | `[成功]` |
| 切换模式前后看群成员列表 | **成员数不变**（任务书 6.(4)：成员数据不受伤害） |
| 管理员禁言普通成员后，该成员发言 | `[失败]`，提示被禁言 |

| 解散群后再做任意操作 | 全部 `[失败]` |

#### B · 多产品体系（主界面 `[4]` 账号中心）

**先分清三层。** 任务书里的「服务」指的是 **QQ / 微信 / 微博 这类微X 产品本身**
（原文：「先后有 QQ、微信、微博等**服务**，可能还将继续推出微商、微唱、微走、微笑等**服务产品**」），
不是"微信支付""滴滴"这类依托于某个产品的第三方应用。

| 层 | 含义 | 代码 |
|---|---|---|
| **有账号** | 是否已持有该服务的号码（微信需先绑定） | `hasPlatformAccount()` |
| **已开通** | 用户**自选**启用该服务（任务书第 4 点） | `isActivated()` / `ActivationManagerFH` |
| **在线** | 当前是否已登录（登录联动，任务书第 5 点） | `isOnline()` / `LoginManagerFH` |

三者互相独立，账号卡片会把它们直接画出来，例如：
`QQ[已开通]  微信[有账号·未开通]  微博[已开通]` —— 意思是"已绑定微信号，
但还没**选择开通**微信服务"；未绑定微信的账号则显示 `微信[无账号]`。

| 操作 | 预期结果 |
|---|---|
| 用「未开通」的服务直接登录 | `[失败]` |
| 开通该服务后再登录 | `[成功]`，且**其余已开通服务一并上线**（登录联动，任务书 5/6.(2)） |
| 服务在线时取消开通 | `[失败]`，须先退出登录 |
| 退出登录后再取消开通 | `[成功]` |
| 微信：未绑定微信号就开通 | `[失败]`；先 `[3]` 绑定再开通 → `[成功]` |
| 重复开通同一服务 | `[失败]`（幂等） |

**跨服务推荐添加（`[9]`，任务书 2.(2)、6.(3)）** —— 四个条件缺一不可。

- **入口拦截**：若本人**未开通「目标」服务**（或没有目标平台账号），按 `[9]` 选完方向后
  会**直接提示去【账号中心】开通**，不再进入诊断屏 —— 因此不会出现「条件①不满足却
  看到候选 N 人」的误解。
- **四条件诊断**：已开通但确实无人可推荐时，界面**逐条回显**四个条件的当前状态，
  其中 ③④ 均以「你的来源平台好友」为基数（交集语义），任一为 0 即可推荐为 0 人。

| 条件 | 说明 |
|---|---|
| ① 本人已开通来源与目标服务 | 微信默认**未开通**，须先到【账号中心】`[1]开通服务`（不满足时入口直接拦截） |
| ② 对方已是你在**来源**平台的好友 | 演示账号初始无好友，须先到【通讯录】`[1]`/`[2]` 添加 |
| ③ 你的来源好友中已绑定**目标**平台账号 | 小明 / 小红 / 路人乙 已绑定微信，路人丙未绑定 |
| ④ 其中**尚不是**你在目标平台的好友 | 已是好友的人不会被再推荐 |

建议演示步骤（QQ → 微信 方向，当前账号：小明）：

1. 【账号中心】`[4]` → `[1]开通服务` → 选 `[2]微信`
2. 【通讯录】`[3]` → `[1]添加QQ好友` → 选 小红
3. 【通讯录】`[3]` → `[9]` → 选 `[1]`（依据 QQ 好友 → 添加微信好友）→ 选中 小红 → `[成功]`

**两个方向要用不同的人演示**：若把 小红 同时加成 QQ 与微信好友，她会同时被
「QQ→微信」和「微信→QQ」两个方向排除（条件④），此时会判定无可推荐。
反方向可换 小红 作为当前账号，先加 小明 为微信好友（不加 QQ），再走 `[9]` 选 `[2]`。

## 5. 数据存档与恢复初始状态

三个存档文件在**程序运行目录**下生成（已加入 `.gitignore`）：

| 文件 | 内容 |

```bash
rm -f save_activation_fh.dat save_friends_fh.dat save_groups_fh.dat
```

（Windows PowerShell：`Remove-Item save_activation_fh.dat,save_friends_fh.dat,save_groups_fh.dat -ErrorAction SilentlyContinue`）

自动演示创建的临时文件（`demo_save_*.dat`）在演示段末自行清理，不会残留。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 中文显示为乱码 | Windows 下用 MSVC 构建（工程已加 `/utf-8`），或用 Windows Terminal 运行 |
| 按键要按回车才生效 | 真实终端下**无需回车**（单键直读）。只有把输入/输出重定向（管道、脚本）时，程序才回退为逐行读取，此时需自行发送换行 |
| 屏幕没有清屏、内容不断追加 | 同上，非终端环境下不发送清屏序列 |
| 演示没有颜色 | 输出被重定向，或终端不支持 ANSI；用 `FH_DEMO_COLOR=1` 强制开启 |
| 演示之间没有暂停 | 同"按键要按回车"：非交互终端会自动跳过暂停 |
| 演示自检汇总出现红色「与预期不符」 | 说明有校验项的结果和预期不一致，请把该段输出与本文 §3.3 的数字对照排查 |
| 想看某一步失败的具体原因 | 工作台底部提示条会给出中文原因；自动演示则看该行末尾的「（应失败…）」标注 |
| 按键后标题栏被顶出屏幕、界面多跳一段 | 已修复：整帧重绘按终端**可视行数**裁剪，输出行数与列宽都受窗口约束，任何窗口高度下整帧都完整可见 |
| 列表太长显示不全 | 界面只画放得下的条数，并在末尾提示「…… 还有 N 条」；放大窗口即可看全（长帮助页会自动分页，不丢内容） |
| 重定向/管道运行，程序直接退出 | 输入流结束时（EOF）程序自行退出，不再空转；`--demo > out.txt` 这种用法会正常跑完演示后退出 |
